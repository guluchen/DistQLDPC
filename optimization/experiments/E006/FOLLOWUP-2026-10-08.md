## Two-stage measurement policy

For subsequent explicitly identified diagnostic screens, run baseline and
candidate serially on the same fixed CPU, interleaving AB/BA/AB with three
repeats per version/case/mode. Record sibling/core interference and resource
telemetry throughout. A transient sibling idle reading below95% is recorded
as interference rather than terminating this diagnostic screen. Preserve all
raw samples; do not select only favorable/quiet timings or pool samples across
different measurement policies. This is an exploratory filter, not a formal
controlled Tier1 PASS, acceptance, merge or research-grade performance claim.

User capacity limits remain mandatory: global spare CPU>50% and no more than
half the remaining spare CPU allocation. Keep one worker, identical baseline/
candidate priority, input, limits and measurement procedure. Resource-capacity
loss still stops work. Tier0, scientific/result checks and timeout interpretation
remain unchanged; semantic mismatches or crashes stop and reject immediately.

Promising candidates then receive a separate controlled server repetition.
An idle server overall is insufficient by itself: validate the assigned core/
sibling lease, isolation, comparable execution settings and cleanup. The
existing strict helper/protocol retains its95% checks; no root helper or
Windows runner was modified by this documentation update.

## Acceptance with measured minor interference

Zero interference or a perfectly idle sibling is not an absolute acceptance
requirement. A future complete experiment may accept the optimization despite
minor interference if retained repeated comparisons show that it does not alter
the performance decision. Require unchanged scientific results, reproducible
overall improvement distinguishable from observed variability and no material
per-case regression. Scientific-result equality alone does not establish that
interference has left the timing conclusion unchanged.

Preregister the assessment before that run: keep all baseline/candidate samples,
compare same-CPU interleaved repeats and resource traces, report per-case medians,
ranges and whether the direction persists across observed interference levels.
If needed, obtain an independent repeat in a quieter window to resolve the
decision; do not discard slow runs, select favorable windows retrospectively,
invent a universal interference percentage or claim that correlation proves
absence of bias. If interference/variability can change the accept/reject
decision, retain INCONCLUSIVE. User spare-capacity limits and correctness guards
remain mandatory. This instruction removes an absolute zero-interference veto;
it does not retroactively complete E006 or bypass the scientific tier sequence.
